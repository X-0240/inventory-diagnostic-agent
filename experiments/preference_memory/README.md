# 未启用能力：偏好记忆与遗忘（评估后本期不做）

这里放的是「长期记忆」能力的设计与实现草稿，**没有接入主链、也没有建表**（`inventory` 库仍是 13 张业务表）。

## 为什么不接

1. 与项目核心叙事（状态机约束下的写操作正确性）关系弱，属于"凑能力覆盖"而不是补核心缺口。
2. 记忆会污染决策：一条过期偏好若不被遗忘，Agent 会一直按错的走。要做就得同时做过期与冲突处置，成本不低。
3. 评审会追问的重点是主链的深度（幂等、并发、回滚、审计），不是记忆的增删改查。

## 如果以后要启用

1. 按契约 10.9 走变更流程：升契约版本号、记录理由与影响面；
2. 执行 `003_preference_memory.sql` 建表（含生成列 + 唯一索引，强制同键只有一条 ACTIVE 记忆）；
3. 把 `memory.py` 放回 `src/inv_agent/`，并在计划开头调用 `sweep_expired()`、在归因信号里带上 `recall_for_sku()` 的结果；
4. 补测试：记住/召回/冲突取代/显式遗忘/到期遗忘/不同范围隔离。
