## 改动前的基线（同一模型、同一批信号）

| 配置 | schema 通过 | 平均延迟 | 输出 token | 说明 |
|---|---|---|---|---|
| 旧提示词（未限输出） | 3/3 | 15134 ms | 2373 / 3827 / 4244 | 提示词没写长度约束，模型输出大量解释 |
| 旧提示词 + max_tokens=400 | 0/3 | 2484 ms | 400 / 400 / 400 | 被截断成空内容，直接解析失败 |

## 结论

- 诊断节点的延迟**主要来自输出长度**：旧提示词下模型输出 2.4k–4.2k token，是入口层（65–122 token）的几十倍。
- 单纯压 `max_tokens` 不可取：400 时输出被截空，3/3 全部解析失败。
- 有效做法是先**收紧提示词**（限条数、限字数、禁止额外字段），再把 `max_tokens` 当安全网（800），而不是当提速手段。
