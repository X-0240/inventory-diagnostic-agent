# 批量与投影性能对照（连接复用 / 并发 / 投影）

日期：2026-09-28 ｜ 版本：v1.7 之后的文档补充 ｜ 状态：本次复测，含优化前后对照

## 一、为什么补这份文档

README 里「连接复用：200 个 SKU 的批量计划从约 5 分钟降到 18.7 秒」这条数字此前只写在 README，
没有独立的测量记录。本次在同一台机器、同一批数据上重测，并补上对照，
让这条数字能说清「怎么测的、对照是什么」。

同一批补测里还覆盖了两项：批量的 4 路并发，以及事实投影（把本地事实写进载体库）的批量提交。

## 二、口径（测前先定）

- 数据：演示数据 W20/W21，200 个 SKU（`config.GEN_SKU_LIMIT=200`）
- 模式：桩模式（不调真实模型）。触发方式：进程环境里把 `LLM_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL`
  置空——`llm.py` 在这三个变量任一为空时返回 Stub
- 数据库：Docker MySQL 8.4（容器 `inv-mysql`）
- 并发：单 worker，另有注明 `--workers 4` 的一组
- 命令：`PYTHONPATH=src .venv/Scripts/python -m inv_agent.cli plan-period --period 2011-W21 --force`
- 计时口径：从进程启动到退出的墙钟（含解释器启动），每组跑 3 次

## 三、结果

| 配置 | 墙钟 | 相对倍数 |
|---|---|---|
| 每次操作新建连接（等价模拟旧实现） | 164.8 秒（1 次） | 1.00× |
| 连接复用（当前实现，单 worker） | 12.70 / 12.73 / 12.74 秒 | 约 13.0× |
| 连接复用 + 4 路并发 | 8.74 / 8.78 / 8.74 秒 | 相对单 worker 约 1.45× |

输出一致性（确认对照只变了连接策略）：三种配置的业务结果完全相同——200 个 SKU、101 个候选、
配额选中 20、连续确认进入诊断 16、建议 154 条、人工接管 0、错误 0。
其中 154 / 16 / 0 / 0 与 v1.1 记录的演示数据一致。

## 四、优化前那一次是怎么测的

旧实现已从代码里移除，仓库中没有保留可切换的旧路径，所以本次**没有回退代码**。
做法是用一个临时驱动脚本（不入库）把 `db._thread_conn` 包一层：顶层操作开始前关闭上一个连接，
等价于「每次操作都重新建连」，然后调用同一个 `graph.run_period`，跑同一批数据、同一周期。

已知偏差：这是对旧行为的**等价模拟**，不是旧代码本身。它的参照物是 README 里记录的历史值「约 5 分钟」。

## 五、与历史记录的差异

| 项 | README 记录（v1.3，2026-09-26） | 本次复测（2026-09-28） |
|---|---|---|
| 优化后·单 worker | 18.7 秒 | 12.70–12.74 秒 |
| 优化后·4 路并发 | 11.6 秒 | 8.74–8.78 秒 |
| 并发倍数 | 1.61× | 1.45× |
| 优化前 | 约 5 分钟 | 164.8 秒（等价模拟） |

本次每一项都比记录更快、并发倍数略低。**原因未定位**：可能来自机器当前状态、
Docker/WSL 网络延迟差异，或 v1.3 之后代码路径的变化。方向结论一致（连接复用带来约一个数量级，
但在桩模式下并发的可重叠空间有限），**对外不再引用 18.7 秒这个单点值**，改用本次区间。

## 六、局限

- 优化前是等价模拟而非旧代码，只能证明方向与量级，不能证明「当时确实是 5 分钟」
- 桩模式测的是「无模型等待」时的批量开销；真实端到端耗时的瓶颈在模型侧
  （真实模型单次诊断 13.3–15.1 秒，见 `docs/LLM延迟对照_20260926.md`）
- 单机、单实例 Docker MySQL，未覆盖多进程共享缓存等二期场景

## 七、投影性能（补充测量）

口径：`PYTHONPATH=src .venv/Scripts/python scripts/project_to_commerce.py`，
把本地库的事实先清空再整批写进载体库 `commerce`，计时为进程启动到退出的墙钟，跑 3 次。

| 次 | 墙钟 |
|---|---|
| 1 | 5.52 秒 |
| 2 | 5.08 秒 |
| 3 | 5.02 秒 |

区间 **5.02–5.52 秒**。写入行数：`product` 200、`inventory_snapshot` 56000、`sales_daily` 33175、
`inbound` 3132，共约 5.8 万行——与上一轮投影后的记录一致，说明重复投影是可重建的。

README 此前记录的「约 5.4 秒」落在本次区间内，方向与量级都吻合；本次起 README 改用区间口径。

**优化前（逐行 INSERT，记录为「450 秒未跑完」）本次没有复现**：复现它需要在代码里退回逐行写入，
一次要 7 分钟以上且当时并未跑完，拿不到确定值。这项只保留历史记录，不作为本次对照的一部分。
