# 多 Agent 对照实验（单 Agent vs 证据收集+归因）

时间：2026-09-26；模型：deepseek-v4-flash；temperature=0；样本 10 个 SKU（周期 2011-W30）。

口径：A 臂＝生产路径（一次调用出结论）；B 臂＝先证据收集（一次调用）再归因（一次调用）。
只报结构性指标，不报分类准确率（没有 ground truth）。判定人与口径即本文件。

| 指标 | A 臂（单 Agent） | B 臂（双 Agent） |
|---|---|---|
| SKU 数 | 10 | 10 |
| 失败数 | 0 | 0 |
| 总调用次数 | 10 | 20 |
| 输出 token 合计 | 22810 | 42869 |
| 每次调用平均延迟 | 10.4 秒 | 10.2 秒 |
| 每 SKU 平均耗时 | 10.4 秒 | 20.4 秒 |
| 证据覆盖族数（均值，满分 3） | 2.70 | 3.00 |
| 三条事实族全覆盖的 SKU | 8 | 10 |
| 两臂结论一致率 | — | 9/10 |

本次估算成本：0.5720 元（累计 2.9421 / 20.0 元）

## 结论

- 看三件事：B 臂多花的调用与 token、B 臂的覆盖族数是否更高、两臂结论是否一致。
- 如果 B 臂覆盖族数没有提高、结论一致率又很高，那「多加一个 Agent」就只增加了成本与故障面，这正是本项目选单 Agent 的证据；反之则说明该拆。
